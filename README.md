# dsh-codesentry

**让 AI 帮你把整个代码仓库审一遍。**

任务化的代码审计插件 · 跑在 DeepSeek Harness 里 · 单会话由 agent 自主分工 · 出可直接交付的审计报告

</div>

---

## 它是什么

给它一个代码目录和一组漏洞类型（或一份审计 Skill），它开一个独立的 AI 会话，把整个仓库交给你配的那个模型，由它自己决定怎么读代码、要不要分几个子智能体并行查、怎么汇总，边跑边显示进度，最后沉淀成一份能直接交出去的审计报告。

不是"问 AI 有没有漏洞"的一问一答，而是一个**能把一整趟审计干完**的工作台。分工这件事交给模型自己做——它比你更清楚该按目录拆、按漏洞类型拆，还是一口气读完，插件只在旁边保证它全程只读、不跑偏。

## 为什么用它

| 痛点 | dsh-codesentry 的解法 |
|---|---|
| 大仓库一次读不完，模型只能抽样 → 覆盖率是个谜 | **交给 agent 自己分工**：整个仓库连同完整文件清单交给模型，它自行决定单会话硬读，还是用子智能体按目录/模块/漏洞类型并行开查，覆盖率由它自己汇报 |
| 任务越跑越长，前面读过的调用链被上下文挤掉 | 拆出去的子智能体各有独立上下文，读再多也不挤占主会话预算；要不要拆、拆多少，模型按仓库大小自己权衡 |
| 硬切片会把 `controller → service → dao` 的污点流切断 | 不再机械切片——模型看到的是整仓文件清单，能顺着调用链跨目录去追 source→sink，需要时再自己汇总核对 |
| 报告靠手写，格式乱、没法交付 | 一键导出 **Markdown / HTML / JSON / SARIF**，带报告编号、风险分布、漏洞详情、**PoC 请求包** |

## 核心能力

- **两种审计模式** — 按漏洞提示词（内置）审，或完全按一份 `SKILL.md` 审计 Skill 执行
- **agent 自主分工** — 整仓交给模型，它自行决定单会话硬读还是用子智能体并行开查；插件全程锁死只读，子智能体也不例外
- **实时进度** — 百分比 / 当前阶段 / 工具调用数 / 已发现漏洞数 / 运行时长，全程可见
- **暂停继续** — 运行中可暂停，继续时复用同一会话从中断点接着审
- **漏洞管理** — 按任务 / 状态 / 严重级别筛选，详情含证据代码、PoC、修复建议
- **专业报告** — 4 种格式，深色封面 HTML 可直接交付或归档
- **Agent 原生** — 斜杠命令 `/audit` + `code_audit_*` 工具，可被任意会话驱动

## 快速开始

```bash
# 1. 安装（DSH 插件，profile 换成你实际在用的那个，如 web / desktop / tui）
dsh plugin --profile web add github:414s857/dsh-codesentry

# 2. 重启客户端后，左侧导航出现「代码审计」入口
# 3. 新建任务 → 选代码目录 + 勾漏洞类型 → 运行
```

## 怎么用（三步）

1. **建任务** —— 填名称、选代码目录、勾要审的漏洞类型（或选一个审计 Skill）、选调度方式（手动 / 定时 / Cron / 固定间隔）
2. **跑起来** —— 点「运行」，看进度条和阶段推进；随时可暂停 / 继续
3. **看报告** —— 修完后点「报告」导出 Markdown / HTML / JSON / SARIF，或直接复制 PoC 去验证

## Agent 工具

`code_audit_*` 系列工具让 AI 会话自己建任务、跑审计、上报漏洞与进度、导出报告。

## 配置

几乎所有东西都能在**界面里的「设置」页**直接调，改完即生效，不需要碰配置文件。想一次改到默认值，再动 `cordis.patch.yml`：

| 项 | 默认 | 说明 |
|---|---|---|
| `maxConcurrentRuns` | `2` | 同时跑几个任务。机器扛得住可以调高，想省资源就调低 |
| `llmRetryCount` | `3` | 模型调用失败重试几次 |
| `llmRetryDelayMinutes` | `5` | 每次重试间隔几分钟 |
| `defaultProvider` / `defaultModel` | 跟随 DSH | 不填就用宿主当前的默认模型，填了就认这里的 |

```yaml
# profile 的 cordis.patch.yml，只写你想改的那几行
- id: codesentry
  config:
    maxConcurrentRuns: 4
```

数据目录（`dataDir`）一般不用动，默认就是下面「存储」里那个位置。

## 存储

数据就放在这一个目录里，卸载时一起带走，不散落在别处：

```text
${DSH_HOME}/storages/codesentry/
├── codesentry.db              # 全部任务 / 运行 / 漏洞 / 提示词 / 技能 / 设置
├── trajectories/<runId>.jsonl # 每次运行的完整过程流水，出问题好复盘
└── reports/                   # 导出的报告都在这里留档
```
